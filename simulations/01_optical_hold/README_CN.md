# 01｜光强定点保持

本案例只运行软件仿真：以归一化 `led_current` 调节归一化 `optical_intensity`，目标为 `0.5`。输入边界为 `[-1, 1]`，软件停止阈值为 `3`。终值绝对误差不超过 `0.03`、超调不超过 `0.1`、5 秒内稳定、至少保持 2 秒，20 次评价的成功率 Wilson 下界不低于 `0.8`。阈值不得为得到某个结果而放宽。

历史开发演练预期进入 `capability_gap`；这是教学分支说明，不保证本次运行的结论。最终状态只能由本任务的真实上传、冻结条件和 Kernel 裁决确定。

## 1. 准备环境并启动 CFDC

在终端运行：

```bash
cd "/Users/huangyichuan/workspace/THU/control-agent"
uv sync --locked
uv run python app.py
```

打开 `http://127.0.0.1:7860`。在“设置”中填写你选择的 Base URL、Model 和 API Key，点击“测试当前配置”。用户可以选择 Ollama、DeepSeek API 或 OpenAI API；开发验证模型是本地 `gemma4:e4b`。为了让本练习的自然语言入口更确定，建议关闭“新任务使用内置知识库”，但这不是对日常模型选择的限制。不要把真实 API Key 写入案例文件或截图。

另开 MATLAB，复制以下命令。仓库若已移动，只改 `cd` 的路径；`setup_case` 会自动添加公共运行时目录。

```matlab
cd('/Users/huangyichuan/workspace/THU/control-agent/simulations/01_optical_hold')
lab = setup_case();
```

`lab` 应包含 `case_dir`、`config`、`model_name` 和 `model_path`。需要单独重建模型时运行 `modelPath = build_model();`。

## 2. 按字段新建任务

在“引导工作台”新建自定义任务，依次填写：

| 页面字段 | 填写值 |
| --- | --- |
| 设备与目标 | 复制 [01_task_description.txt](prompts/01_task_description.txt) |
| 任务类型 | 保持在目标附近 |
| 输出 1 名称 / 单位 | `optical_intensity` / `normalized` |
| 输入 1 名称 / 输入单位 | `led_current` / `normalized` |
| 输入下限 / 输入上限 | `-1` / `1` |
| 软件试验停止阈值 | `3` |
| 参考目标 | `0.5` |
| 评价区域（适用的工作范围） | 归一化光强定点附近的软件仿真工作区 |
| 采样间隔 / 每次运行时长 / 重复运行次数 | `0.02` / `20` / `20` |
| 稳定后允许偏离目标多少 | `0.03` |

展开“性能要求与预算（可选）”，在“明确的性能要求”中勾选并填写：允许超过目标 `0.1`、希望多少秒内稳定 `5`、至少保持多少秒 `2`、重复试验成功率下限 `0.8`。点击“校验并核对”，逐项核对后勾选“我已核对目标、软件试验边界与预算”，再点击“确认软件边界并开始”。

## 3. 提交真实的设计来源说明

在“补充已知现象”或页面当前自然语言输入框中完整复制 [02_diagnosis.txt](prompts/02_diagnosis.txt)。它以“以下来自固定仿真模型的设计说明，不是本任务实测结果”开头，列出固定模型的设计条件，同时明确实际响应、噪声、重复性和性能表现仍未测得。它不声称已经运行实验，也不提供控制器数值或性能结论。

如果页面继续逐维追问，只从 [03_clarifications.txt](prompts/03_clarifications.txt) 复制与当前问题相符的完整一段，并保留段首来源说明。页面追问实测现象时仍应如实回答“不知道”；不要补写未运行的实验结果。

页面记录完这些设计条件并显示“继续下一步”后，点击“继续下一步”，再进入软件来源选择。

## 4. 选择软件来源并完成预检查

选择“外部软件仿真”，点击“确认数据来源”。当页面显示“下载采集请求包 ZIP”时下载本轮包，保持下载文件名不变。先在 MATLAB 对这一个实际下载包执行机器预检查，再做页面中的人工确认：

```matlab
cfdcSim.preflight(lab)
```

也可以显式传入任意下载路径，无需把文件改名或移动到案例目录：

```matlab
cfdcSim.preflight(lab, '/absolute/path/to/downloaded-operator-package.zip')
```

确认预检查通过并实际核对测量与控制通道、单位、记录工具、停止条件和初始条件后，才选择“检查完成，可以继续”。“操作员说明”可复制 [04_operator_note.txt](prompts/04_operator_note.txt)。任一项不确定时选择“需要澄清”并如实说明，不能照抄完成说明。

## 5. 运行识别并上传全部 CSV

对同一个采集请求包运行：

```matlab
identification = cfdcSim.run_identification(lab);
identification.run_dir
identification.files
```

省略路径会打开选择器；也可把下载包的绝对路径作为第二个参数。运行结束后，在页面“选择实验数据”中选择 `identification.files` 列出的全部 CSV，再点击“检查上传数据”。不要上传空模板、不要漏掉某次重复，也不要修改协议标识。若停止条件触发，应如实勾选“实验触及限制，已停止”。

## 6. 核对并冻结评价约定

上传通过后，系统自动提取特征、形成和审查候选。进入冻结步骤后，核对页面列出的参考目标、边界、采样间隔、20 秒时长、20 次重复和全部性能要求。勾选“我已核对冻结约定，确认进入开发评价”，点击“确认并冻结评价约定”。冻结后不要用旧请求包代替新包。

## 7. 运行开发评价并上传结果 ZIP

点击“准备本轮外部运行包”，再点击“下载本轮完整运行包 ZIP”。这是本轮输入请求，不是已完成结果。在 MATLAB 运行：

```matlab
evaluation = cfdcSim.run_evaluation(lab);
evaluation.run_dir
evaluation.files
evaluation.result_zip
```

在“选择完整结果 ZIP”中只选择 `evaluation.result_zip` 指向的返回包，然后点击“校验并提交本轮轨迹”。不要回传下载的请求包，也不要只上传汇总指标。

## 8. 按实际分支继续候选或全新确认

若 Kernel 进入 `capability_gap`，阅读页面原因并保留产物；它不是性能通过。若页面提供“开始有界外部调优”，每次只点击一次，下载该候选自己的新运行包，并重复第 7 步。若进入“独立确认”，必须下载确认包并重新运行全新轨迹，不能复用开发评价或调优数据。只有页面本次动作决定实际分支。

## 9. 导出最终记录

任务到达终态后，在“评价结果”查看结论和指标。使用“下载原始报告”保存报告；需要完整审计材料时打开“专家工具”，在“下载”中选择“下载完整产物”。保留 WebUI 下载的原始包、MATLAB `runs/` 返回物和最终导出，三者用途不同。不要把本地运行工件提交到 Git。
