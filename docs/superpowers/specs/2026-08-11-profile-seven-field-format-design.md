# Profile 七项必填回答格式设计

## 目标

将 `dataset/control_problem_prompts.md` 与
`dataset/control_problem_prompts_cn.md` 中各 200 条 Profile 测量回复改为一致的
两段式自然语言格式：先逐项回答当前 Profile 真正需要的参数，再将其余仍有价值的
案例数据放入“额外信息”。修改只改善数据组织和可粘贴性，不改变案例数值、单位、
模型含义或软件仿真安全边界。

## 统一格式

使用一阶输入输出比例与时间常数 Profile、且原记录已经明确给出七项数值的 23 个
案例，以“七项必填回答”开头，并按以下固定顺序恰好出现一次：

1. `已知输入变化量`
2. `最终输出变化量`
3. `63% 响应时间`
4. `输入仿真下限`
5. `输入仿真上限`
6. `输出仿真下限`
7. `输出仿真上限`

每一项使用独立的自然语言项目符号，明确给出案例对应的信号、有限数值和单位。
英文文件使用严格对等的固定标签和顺序：

1. `Known input change`
2. `Final output change`
3. `63% response time`
4. `Input simulation lower bound`
5. `Input simulation upper bound`
6. `Output simulation lower bound`
7. `Output simulation upper bound`

其余 177 个振荡器、双积分器、状态空间、MIMO、注册非线性或其他专用 Profile
不补造七项数值。它们使用“Profile 专用必填回答”或
`Profile-specific required answers`，将现有物理参数和完整软件模型分别标为
“已声明的 Profile 参数”与“可执行软件模型”。

两种格式都保持自然语言，不引入 `input_change=...` 等内部字段赋值语法，也不引入
JSON。

## 额外信息

必填回答之后统一增加“额外信息”或 `Additional information`。现有回复中的下列
内容按案例需要保留在该段：

- 显著纯时延；
- 热容、质量、惯量、阻尼、刚度等 Profile 专用物理参数；
- 传递函数、状态空间或注册非线性模型说明；
- 采样间隔、软件仿真时长、初值、输入幅值和参数变化倍率；
- 扰动、比较控制器或其他有助于复现实验的既有软件记录。

每条回复末尾继续保留“所有范围只作为软件仿真停止边界，不授权控制实体硬件”的
双语安全声明。

## 数据迁移

迁移以现有每条 Profile 回复中的数值和单位为唯一来源。一阶案例原紧凑首段与
“已有记录”段中重复表达的七项数据合并为新的逐项回答；专用 Profile 案例把原首段
与完整模型段标记为 Profile 专用必填回答。记录配置和其他非必填内容移动到额外信息。
不得补造新数值，也不得因格式化改变正负号、量纲、信号名称或边界。

英文与中文同编号条目必须继续表达同一组必填参数和同一类额外信息。两个文件仍各
包含 200 条，与技术语料编号一一对应。

## 验收与测试

扩展 `tests/test_control_problem_prompts.py`，先建立失败契约，再执行数据迁移。测试
至少验证：

- 23 个适用案例恰好包含一组七项固定标签，顺序正确；
- 七项标签后都有非空自然语言回答，并同时包含数值和单位；
- 其余 177 个案例不包含伪造的七项值，而是包含 Profile 专用参数与完整模型回答；
- 每条均存在“额外信息”段和软件仿真边界安全声明；
- assignment token、JSON、旧八项诊断回填标题不会重新出现；
- 恒温器、汽车巡航以及传递函数、状态空间、注册非线性代表案例的原有关键数据仍在；
- 双语数据仍保持 200 条结构对齐，控制问题描述不被修改；
- `pytest -q`、`python -m ruff check .`、`python -m compileall -q cfdc tests main.py`
  与 `git diff --check` 全部通过。

## 非目标

本次不修改运行时 Profile 模板、规格提取器、Gradio 组件或控制器算法；也不把七项
通用回答替代为 JSON。专用 Profile 仍可使用额外信息中的必要参数完成后续建模。
